# Architecture cible documentaire

Vision → domaines → capacités → services cibles → phases → activation. Un service documenté n’est ni développé, ni déployé, ni activé par défaut. Les données sont possédées par leur domaine autoritatif ; les événements et projections propagent des copies gouvernées.

## Niveaux de documentation

| Niveau | Contenu |
|---|---|
| D0 | Service identifié |
| D1 | Mission et frontières |
| D2 | Capacités, données et dépendances |
| D3 | API, événements et workflows |
| D4 | Sécurité, résilience et observabilité |
| D5 | Prêt à développer |
| D6 | Production |
